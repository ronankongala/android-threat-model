## NIST SP 800-163 Rev. 1

Source: NIST Special Publication 800-163 Revision 1, "Vetting the Security of Mobile Applications", April 2019 (final, 04/19/19; supersedes SP 800-163 of 01/26/2015). Authors: Michael Ogata, Joshua Franklin, Jeffrey Voas, Vincent Sritapan, Stephen Quirolgico. DOI: https://doi.org/10.6028/NIST.SP.800-163r1. Publication page: https://csrc.nist.gov/pubs/sp/800/163/r1/final. The official PDF was downloaded and its text extracted on 2026-11-02; every name and quote in this section was read from that text.

What the publication contains that matters here:
- Section 3 describes the app vetting process: 3.1 App Intake, 3.2 App Testing, 3.3 App Approval/Rejection, 3.4 Results Submission, 3.5 App Re-Vetting. The Ghera benchmarks fit step 3.2, where a test tool analyzes an app and its report "identifies any detected software vulnerabilities or potentially harmful behaviors". Each Benign and Secure app is a known-positive or known-negative input for such a tool.
- Section 2.1.1, Table 1 "NIAP Functional Requirements", lists requirement names only (its footnote says "many, but not all" are listed and points to the NIAP Protection Profile for the full list). The Protection Profile itself was not downloaded, so the NIAP table below maps by requirement name only and every row is Partial.
- Appendix B "Android App Vulnerability Types" sorts Android app vulnerabilities into levels A (class), B (sub-class) and C (individual vulnerability). Table 3 lists the eight A-level types; Table 4 gives the A to C hierarchy.

Caution on Table 4: the text extraction mixed up the columns of Table 4, so which entry sits under which parent cannot be read reliably. The mapping below is made at A level (Table 3). The "Table 4 entries" column quotes entry names that appear verbatim in the extracted text and does not say whether an entry is level B or level C, or which parent it has.

Fit values follow `BATCH-RULES.md`: Direct when the type describes the benchmark's weakness as it is, Partial when it covers only part of it or needs a caveat. A benchmark can also appear under a second type, marked "(secondary)". Benchmark names are the folder names in `benchmark-index.md`, grouped by Ghera category; the reasons come from `benchmark-index.md`, `other-categories-mapping.md` and the ICC and Web threat models.
